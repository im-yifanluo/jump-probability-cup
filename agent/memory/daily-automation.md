Daily automation (user-approved 2026-06-12, "fully automate"): `scripts/daily_run.py --hours 48 --submit` prices and upserts every match kicking off within the horizon (initial pass = create, later passes = PATCH only changed values; never submits past kickoff; prints NEEDS ATTENTION list of prior-priced players). ORCHESTRATION (designed 2026-06-13 per user requirement "don't run the hardcoded pipeline if the agent runs"): agent-primary with deterministic fallback that DEFERS. The agent (/matchday) runs `daily_run.py --submit --agent`, which writes a heartbeat to data/logs/agent_last_run. The OS crontab runs `daily_run.py --submit --defer-to-agent 45` — if the heartbeat is <45 min old it skips entirely (prints "deferring to agent", logs deferred, does NOT submit). So the crontab never overwrites the agent's research-informed values; it only fires when the agent didn't run (app closed/crashed). Verified both directions. Install command (with --defer-to-agent 45) is in the README "Automation architecture" section; user must install it themselves (classifier blocks Claude writing crontab).

The routines are `.claude/commands/{morning_run,matchday,night_run}.md` (read-and-execute). CURRENT SCHEDULE (REBUILT 2026-06-26 to DYNAMIC self-scheduling — kickoff times MOVE day-to-day (e.g. Fri 2/7/10pm CT vs Sat 4/6:30/9pm CT), so fixed-time passes mistime them). ONE fixed anchor: **07:48 morning_run** (48h broad — evaluate last night, set bot2 experiment, FLAG bot1 promotion, submit both, OUTPUT today's bot1 predictions to chat, THEN schedule the day's final passes). It runs `scripts/schedule_day.py` (50-min lead; system-local tz via `.astimezone()` so a 03:00Z/10pm-CT game → a 9:10pm-CT fire on the correct LOCAL date), CronDeletes any existing `[AUTO-DAY]` one-shots, and creates ONE one-shot ~50min before EACH of today's kickoff waves: kind=final → matchday.md 5h (lineup-fresh); the LAST wave → night_run.md 26h (prices ALL of tomorrow + OUTPUTs tomorrow's bot1 predictions for pre-fill). Passes thus adapt to each round's times with no overlap. SAFETY (verified feasible 2026-06-26): daily_run never submits past kickoff (a late fire only loses freshness, never posts a stale price); the `[AUTO-DAY]` marker dedups; only future waves are scheduled. This replaced the earlier fixed 4-cron and 6-cron stacks (experiment.md/bot1_production.md DELETED). ALL session-only (durable:true does NOT persist here — dies when Claude exits) + 7-day expiry; survive a context compaction (same REPL) but NOT a restart. ROBUSTNESS: do not rely on the crons — trigger each run by sending its prompt manually. QUALITY ACROSS COMPACTION/SESSIONS is FILE-BACKED, not context-dependent: the routines are self-contained, docs/strategy_v4.md is the canonical strategy, data/bot2_experiment.yaml the live experiment, and the memory files auto-load each session — so any agent reads those and operates identically. Logging (added 2026-06-12, user-required): every daily_run appends a summary block to data/logs/runs.log; every real submission appends per-market rows to data/logs/submissions.csv (domain layer, all paths); every /matchday run MUST append its full report to data/logs/matchday_reports.md (skill step 6).
